# Свой сервер LotusTok

Сервер даёт моду бейджи, подтверждение аккаунта, градиенты, магазин плагинов,
отчёты о сбоях и (по желанию) бота в Telegram. Обновления мода хранятся
отдельно, статикой. Всё работает на самом простом VPS (1 ядро, 512 МБ).

## Что нужно

- VPS с **Ubuntu 22.04 / 24.04 или Debian 12**. На Debian 13 / Python 3.13 сервер
  не запустится: он использует модуль `cgi`, который в 3.13 убрали.
- **Домен**, у которого A-запись смотрит на IP сервера. Мод ходит только по
  https, без домена и сертификата бейджи работать не будут.
- Открытые порты 80 и 443 (если стоит ufw: `ufw allow 80,443/tcp`).
- По желанию: токен бота от @BotFather и ваш числовой Telegram-ID
  (его показывает @userinfobot).

## Установка

Скопируйте эту папку целиком на сервер (`scp -r lotustokserver root@IP:/root/`)
и запустите из неё:

```bash
cd /root/lotustokserver
sudo bash install.sh ваш.домен.ру вы@почта.ру
```

С ботом и уведомлениями о входе в панель:

```bash
sudo bash install.sh ваш.домен.ру вы@почта.ру 123456789 1234567890:AAE...токен
```

Скрипт ставит nginx, certbot и Python, создаёт пользователя `lotustok`,
кладёт сервер в `/opt/lotustok`, заводит службы `lotustok-badges` и
`lotustok-bot`, настраивает https и пишет в конце **пароль панели**
(логин `admin`). Он показывается один раз: сохраните и сразу смените
в панели. Повторный запуск обновляет код сервера, не трогая базу, пароль,
токен и плагины.

Проверка:

```bash
curl https://ваш.домен.ру/api/badges
systemctl status lotustok-badges
journalctl -u lotustok-badges -f
```

## Что прописать в моде

Мод пока смотрит на сервер MargyT. Когда сервер поднят, в двух местах
меняется адрес (скажите мне домен, я это сделаю и пересоберу):

| Где | Что |
|---|---|
| `inject/java/cat/narezany/margyt/Badges.java`, `SERVER` | `https://ваш.домен.ру/api` |
| `inject/java/cat/narezany/margyt/Updater.java` | `https://ваш.домен.ру/updates/version.json` |

Если нужен свой патчер, то же самое в `patcher/catalog.json` и в
`patcher/.../Catalog.kt`, `Telegram.kt`.

## Бейджи

- **Панель:** `https://ваш.домен.ру/admin`. Там выдаются и снимаются бейджи
  по числовым ID аккаунтов TikTok, создаются новые бейджи с картинкой,
  добавляются плагины для магазина.
- **Из консоли на сервере:**

```bash
cd /opt/lotustok
sudo -u lotustok ./badgectl list
sudo -u lotustok ./badgectl grant owner 1234567890123456789
sudo -u lotustok ./badgectl who 1234567890123456789
sudo -u lotustok ./badgectl take owner 1234567890123456789
```

Начальный набор бейджей лежит в `badges.json` (владелец, поддержка,
помощник), в нём пока никого нет.

## Обновления мода

Положите на сервер два файла в `/var/www/lotustok/updates/`:

```bash
scp build/margyt.apk root@ваш.домен.ру:/var/www/lotustok/updates/lotustok-1.0.0.apk
scp version.json     root@ваш.домен.ру:/var/www/lotustok/updates/version.json
```

В `version.json` поле `url` должно вести на этот apk
(`https://ваш.домен.ру/updates/lotustok-1.0.0.apk`), а `version` быть больше
установленной (это номер LotusTok из файла `VERSION`, не MargyT; см. [ВЕРСИИ.md](../ВЕРСИИ.md)): так телефон узнаёт, что вышла новая версия.

## Бэкап

Всё важное это один файл:

```bash
cp /opt/lotustok/badges.db /root/badges-$(date +%F).db
```

## Что учесть

- Сервер читает страницы профилей TikTok для подтверждения аккаунта. Если TikTok
  режет запросы с адресов дата-центров, подтверждение может не проходить:
  VPS в другой стране/другого провайдера иногда помогает. Формат страницы
  TikTok может поменяться, это зона риска у любого такого сервера.
- Телефоны со старым MargyT продолжают ходить на сервер narezany. Ваши бейджи
  увидят только сборки, собранные с вашим адресом.
- Серверный код под GPL-3.0 с доп. условиями (`ADDITIONAL-TERMS.md`): сохраняйте
  указание на автора оригинала и на то, что это форк.
